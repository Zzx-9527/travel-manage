# 前端接口对接说明（给前端开发/AI）

## 通用约定

- 基础地址：`http://localhost:8081/travel`
- 所有接口返回统一 JSON 结构：
  ```json
  { "code": 1, "msg": "提示信息", "content": "业务数据" }
  ```
  `code = 1` 成功，`code = 0` 失败，业务数据在 `content`。
- 分页接口的 `content` 结构：
  ```json
  {
    "content": [ /* 当前页数据 */ ],
    "totalElements": 总数
  }
  ```
- **鉴权（已强制生效，详见第 8 节）**：除登录、注册、接口文档、上传后的图片静态资源外，所有接口必须带请求头
  `Authorization: Bearer <token>`，`token` 来自登录接口返回值。
  - 未带 / 过期 / 被踢下线 → **HTTP 401**，`{ "code": 0, "msg": "..." }`，前端清 token 并跳登录页；
  - 已登录但角色不足 → **HTTP 403**，`{ "code": 0, "msg": "无权限访问" }`，前端只提示不跳转；
  - 业务失败仍是 **HTTP 200 + `code: 0`**，按 `msg` 提示。
- **内容类型约定**：
  - `targetType`：`1=攻略，2=景点，3=路线`（收藏用）
  - `auditStatus` / `status`：`0=待审核，1=已通过，2=已驳回`（攻略/路线用）
  - `isRead`：`0=未读，1=已读`；`type`：`0=系统，1=订单，2=审核`（消息用）

## 1. 后台统计卡片

- **GET** `/travel/dashboard/stats`，无参数
- 返回：
```json
{ "code": 1, "content": { "userCount": 12, "scenicCount": 48, "strategyCount": 36, "orderCount": 89 } }
```
（用户数 / 景点数 / 攻略数 / 订单数）

## 2. 用户信息（后台"用户信息"菜单 / 个人中心）

- **GET** `/travel/travelUser/myProfile`，**无参数**：用户身份从 `Authorization` 头自动识别
- 返回 `content` 为用户对象，字段：`id, account, nickname, phone, avatar, userRole, status, createTime, updateTime`（**不含密码**）

### 2.1 修改自己的资料（新增，登录即可）

- **POST** `/travel/travelUser/updateProfile`
- Body（三个字段都可选，传哪个改哪个）：
```json
{ "nickname": "新昵称", "phone": "13900000000", "avatar": "/travel/uploads/2026/10/31/xxx.png" }
```
- 返回 `{ "code": 1, "msg": "修改成功" }`
- 身份取 token，**不需要传 id**；`userRole` / `status` 即使传了也会被忽略（防止自己提权）
- 头像遵循"单图覆盖"：保存成功后后端自动删除旧头像文件，前端不要自己删

## 3. 修改密码（后台"修改密码"菜单）

- **POST** `/travel/travelUser/updatePassword`，Body：
```json
{ "oldPassword": "原密码", "newPassword": "新密码" }
```
- 身份取 token，**不需要传 `id`**（传了也会被忽略）
- 成功 `{ "code": 1, "msg": "修改成功" }`；原密码错 `{ "code": 0, "msg": "原密码不正确或用户不存在" }`
- 改密成功后**不会**踢掉已有会话，前端保持在当前登录状态即可

## 4. 消息通知中心

### 4.1 消息列表

  | 参数 | 类型 | 必填 | 说明 |

### 4.4 后台发通知（管理员）
- **POST** `/travel/message/add`，Body：
```json
{ "userId": { "id": 1 }, "title": "标题", "content": "内容", "type": 2 }
```

### 4.5 其他
- **GET** `/travel/message/queryById/{id}`
- **POST** `/travel/message/edit`（同 add 结构）

## 6. 收藏（攻略 / 景点 / 路线，靠 targetType 区分）

> 收藏人一律由后端按 token 识别：`userId` 可传可略（会被忽略），`collectorId` 由后端自动填充。

### 6.1 收藏
- **POST** `/travel/collect/add`，Body 三选一：
```json
{ "targetType": 2, "targetId": 9 }   // 景点
{ "targetType": 3, "targetId": 5 }   // 路线
{ "strategyId": { "id": 3 } }        // 攻略(兼容)
```

### 6.2 我的收藏列表
- **GET** `/travel/collect/queryByPage`
- 参数：
  | 参数 | 类型 | 必填 | 说明 |
  |---|---|---|---|
  | `targetType` | int | 否 | 1攻略 2景点 3路线 |
  | `targetId` | int | 否 | |
  | `page` / `size` | int | 否 | 默认 1 / 10 |
- 普通用户自动只查自己的收藏；管理员可额外传 `collectorId` 指定用户。
- 返回 `content.content` 中按 `targetType` 带出对应对象：`strategyId`、`scenicId`、`routeId`。

### 6.3 判断是否已收藏（按钮回显）
- **GET** `/travel/collect/checkCollected?targetType=2&targetId=9`（不需要 userId）
- 返回 `{ "code": 1, "content": true/false }`

### 6.4 取消收藏
- **POST** `/travel/collect/deleteByUserAndTarget`
```json
{ "targetType": 2, "targetId": 9 }
```
- 也可用 **POST** `/travel/collect/deleteById/{id}`
- 只能操作自己的收藏，越权返回 403。

## 8. 登录鉴权与会话管理（Sa-Token，已上线）

> 本节接口已在后端实现并启用（Sa-Token + Redis 会话），前端按此对接即可。

### 8.1 登录

- **POST** `/travel/travelUser/login`
- Body：`{ "account": "admin", "password": "123456" }`
- 返回：
```json
{
  "code": 1,
  "msg": "登录成功",
  "content": {
    "user": { "id": 1, "account": "admin", "nickname": "管理员", "userRole": 1, "...": "其余用户字段" },
    "token": "a1b2c3d4e5f6...",
    "tokenName": "Authorization",
    "expire": 86400
  }
}
```
- `token` 是**随机串，不是 JWT**，前端不要解析 payload，只负责保存与回传。
- `expire` 单位是**秒**（86400 = 24 小时）。
- **登录限流**：同一 IP 每分钟最多 5 次登录尝试，第 6 次返回 `{ "code": 0, "msg": "操作过于频繁，请 1 分钟后再试" }`（HTTP 200）。
- **禁用账号**：`status = 0` 的用户即使密码正确也会被拒，返回 `{ "code": 0, "msg": "账号已被禁用，请联系管理员" }`；已被禁用的在线用户会被立即踢下线，旧 token 返回 401。

### 8.2 请求头格式

```
Authorization: Bearer <token>
```

`tokenName` 只是头名。**务必使用 `Authorization: Bearer <token>`**（缺了 `Bearer ` 前缀会被判为无效 token，返回 401）。

### 8.3 状态码约定（与旧版不同，重点）

| HTTP 状态 | 触发场景 | 前端处理 |
|---|---|---|
| **401** | 未带 token / token 无效 / 已过期 / 被踢下线 / 在别处登录被顶下线 | 清除本地 token → 跳登录页 → 用 `msg` 提示 |
| **403** | 已登录，但角色不够（如普通用户访问后台接口），或访问他人的订单 | 提示"无权限"，**不要**跳登录页 |
| 200 且 `code: 0` | 业务失败（参数错、库存不足等） | 按 `msg` 提示 |

401 的 `msg` 可能为：

| msg | 含义 |
|---|---|
| 未登录，请先登录 | 没带 token |
| token 无效或已过期 | 过期 / 伪造 / 被系统清理 |
| 账号被强制下线 | 管理员踢人 |
| 账号在别处登录 | 多端登录被顶下线（当前配置为每端独立 token，一般不会触发） |

### 8.4 登出

- **POST** `/travel/travelUser/logout`，带 `Authorization` 头
- 返回 `{ "code": 1, "msg": "已退出登录" }`
- 前端收到成功响应后清除本地 token；**登出后旧 token 立即失效**（这是替换 JWT 的核心收益）。

### 8.5 会话有效期

- 绝对有效期 **24 小时**（`expire = 86400`）。
- **30 分钟无任何请求自动过期**；只要正常发请求就会自动续期，前端无需手动刷新 token。
- token 快过期时不需要特殊处理，过期后按 401 处理即可。

### 8.6 角色

`userRole` 取值：**0 = 普通用户**，**1 = 管理员**（列默认值 0，注册时不需要传）。

| 接口 | 要求 |
|---|---|
| `/travel/dashboard/**`（后台统计） | 管理员 |
| `/travel/travelUser/online`、`/travel/travelUser/kickout/{id}` | 管理员 |
| `/travel/travelUser/queryById/{id}`、`queryByPage`、`edit`、`deleteById/{id}` | 管理员 |
| `/travel/travelUser/register`（注册） | 匿名可访问，服务端强制普通用户 |
| `/travel/travelUser/add`（后台新增用户） | 管理员 |
| 其余业务接口（含文件上传） | 登录即可 |

非管理员访问以上接口返回 **403**。

### 8.7 在线用户与踢人（管理员）

**在线用户列表**
- **GET** `/travel/travelUser/online?page=1&size=10`
- 返回：
```json
{
  "code": 1,
  "content": {
    "total": 3,
    "list": [
      { "userId": 1, "account": "admin", "nickname": "管理员", "userRole": 1, "tokenCount": 1, "loginTime": "2026-10-31 18:20:11" }
    ]
  }
}
```
- `tokenCount` 为该用户当前有效 token 数（多端登录时 > 1）。
- `loginTime` 为该用户最早一次登录的时间（会话创建时间）。
- 列表按 `userId` 聚合，普通用户调用返回 **403**。

**强制下线**
- **POST** `/travel/travelUser/kickout/{userId}`
- 返回 `{ "code": 1, "msg": "已强制下线" }`
- 被踢用户的下一次请求收到 **401 + "账号被强制下线"**，前端按 401 规则处理。

### 8.8 接口文档

- Knife4j 文档地址：`http://localhost:8081/travel/doc.html`（springfox 已替换，旧地址 `/swagger-ui.html` 不再使用）
- 调试接口时可在 Knife4j 的「全局参数」里配置 `Authorization` 头，避免每次手填。

## 10. 文件上传（新增）

- **POST** `/travel/file/upload`，`multipart/form-data`，字段名固定为 **`file`**
- 需要登录（普通用户即可，不要求管理员）
- 限制：单文件 ≤ **10MB**；仅支持 **jpg / jpeg / png / gif / webp**（后端会同时校验后缀和 `Content-Type: image/*`）
- 返回：
```json
{
  "code": 1,
  "msg": "上传成功",
  "content": {
    "url": "/travel/uploads/2026/10/31/8f3c2a1b9d4e4f6a8b7c6d5e4f3a2b1c.png",
    "name": "原文件名.png",
    "size": 20481
  }
}
```
- `url` 是**可直接访问的地址**，拼上域名即可：`http://localhost:8081` + `url`（图片静态资源**不需要 token**，`<img src>` 直接用）
- 失败示例：
  - 类型不支持：`{ "code": 0, "msg": "只支持 jpg/jpeg/png/gif/webp 图片" }`
  - 文件为空：`{ "code": 0, "msg": "文件为空" }`

**单图覆盖约定**：头像、攻略封面、景点封面都只保留最新一张。
前端**不需要**调删除接口——把新 `url` 通过对应的 `edit`/`update` 接口保存后，后端会在入库成功时自动删掉旧文件。

**前端上传示例（axios）**：
```js
const fd = new FormData()
fd.append('file', fileInput.files[0])
const { data } = await axios.post('/travel/file/upload', fd, {
  headers: { Authorization: `Bearer ${token}` }
})
form.cover = data.content.url
```

## 11. 门票订单（库存版接口契约，前端需要同步改造）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/scenicOrders/queryByPage` | GET | 普通用户自动只查自己的订单，管理员可查全部；展示订单 `status` 而非仅 `payStatus` |
| `/scenicOrders/queryById/{id}` | GET | 非本人且非管理员返回 HTTP 403 |
| `/scenicOrders/add` | POST | 必传 `scenicId.id`、`playDate`、正数 `ticketCount`、联系人；用户/金额/状态/订单号由服务端决定，成功 `content` 含 `id`、`orderNo`；5 秒防重只防重复请求 |
| `/scenicOrders/cancel/{id}` | POST | 本人或管理员取消待支付订单；状态变为 2、回补库存，历史可见，重复取消不再次回补 |
| `/scenicOrders/pay/{id}` | POST | 仅订单本人可在创建后 30 分钟内模拟支付；不再走 `/edit` 修改支付状态 |
| `/scenicOrders/edit` | POST | 本期仅允许本人编辑待支付订单的联系人；`userId`、`payStatus`、`totalAmount`、票数和游玩日期等字段不可更改 |
| `/scenicOrders/deleteById/{id}` | POST | 不可删除待支付订单；请改走取消接口，超时取消订单保留历史 |
| `/scenic/stock?scenicId=&playDate=` | GET | 查询成人票可售余量（容量与票库存较小值），仅供展示；无记录为暂未开放，最终以下单原子扣减结果为准 |
| `/scenic/stock/adjust` | POST | 管理员设置单日容量和成人票库存，参数 `scenicId,playDate,capacity,adultStock`，保留已占用数量 |

`status`：`0=待支付、1=已支付、2=已取消、3=已完成`（完成入口本期未开放）；`payStatus` 保留旧历史兼容：`0=未支付、1=已支付、2=旧退款`，不能再把值 2 当作免费票。`cancelReason=TIMEOUT` 显示“已超时取消”，`LEGACY_UNPAID/LEGACY_REFUNDED` 为历史迁移记录。订单 `unitPrice` 为下单时单价快照；存量旧订单无可靠单价快照时可能为 null。仅开放含今天共 30 个自然日，今天到景区截止时间（默认 17:00，Asia/Shanghai）后不可下单；未支付满 30 分钟自动取消并回补。前端不再通过删除订单模拟取消，也不通过 `/edit` 模拟支付。

## 12. 景点详情与浏览量

- `GET /travel/scenic/queryById/{id}` 返回的 `viewCount` 来自数据库；
- 每次访问后端会异步计数，**最多延迟约 60 秒**才写回数据库并反映到接口上；
- 前端不需要做额外处理，也不要自己 `+1`。

## 13. 本次后端变更清单（前端需要改的地方）

按优先级排列，前 4 条不改会导致功能不可用：

| # | 变更 | 前端要做什么 |
|---|---|---|
| 1 | 除登录/注册/文档/图片外，**所有接口强制 token** | 统一在 axios 拦截器里加 `Authorization: Bearer <token>` |
| 2 | 登录返回结构：`token` / `tokenName` / `expire` | 保存 `token`；**不要解析 token**（不是 JWT） |
| 3 | **401 / 403 语义变化** | 401 清 token 跳登录；403 只提示"无权限"，不要跳登录 |
| 4 | 新增登出接口 `POST /travelUser/logout` | 退出登录时调用，成功后清本地 token |
| 5 | 消息/收藏/发布接口不再需要 `userId`（传了也被忽略） | 去掉 `userId`、`collectorId` 参数 |
| 6 | `myProfile` 不再接受 `?id=` | 改为无参调用 |
| 6.5 | 新增自助改资料 `POST /travelUser/updateProfile` | 个人中心改昵称/手机/头像用它；**不要用 `/travelUser/edit`**（管理员专属，普通用户 403） |
| 7 | 后台接口按角色限制，普通用户 403 | 按 `userRole`（0 普通 / 1 管理员）控制菜单与按钮显示 |

| 9 | 订单库存、模拟支付与取消改为独立接口 | 下单不传金额/用户/支付状态；改调用 `/scenicOrders/pay/{id}` 与 `/scenicOrders/cancel/{id}`，不再通过 `/edit` 改支付或通过删除取消；列表显示 `status` 与超时取消原因，处理 403 |
| 10 | 景点 `viewCount` 有 ≤60 秒延迟 | 不需要处理，别自己累加 |

## 前端 3 个易错点（务必遵守）

1. **`userId` / `collectorId` 不再需要传**——后端从 token 取；消息接口如果管理员要按人筛选，必须用嵌套写法 `?userId.id=1`（直接传 `userId=1` 会因类型转换失败报 400）。
2. **`routeId` 传整数**，不需要包对象。
3. 分页列表取数统一用 `res.content.content`（数组）+ `res.content.totalElements`（总数）。
