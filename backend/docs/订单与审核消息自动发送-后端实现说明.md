# 订单与审核状态自动推送 · 后端实现说明

> 目标：攻略/路线/评论**审核完成**、门票订单**下单/支付成功**时，自动向对应用户的消息中心写入一条消息（前端铃铛红点、消息列表、已读逻辑已全部就绪，无需改动）。
> 后端工程：`项目根目录`（Spring Boot + MyBatis，`com.zjx.travel`）。
> 前端契约：消息实体接收人字段为 `userId`（TravelUserEntity 对象）；消息类型 `type`：**0系统 / 1订单 / 2审核**；`isRead`：0未读 / 1已读。

---

## 1. 新建消息发送辅助组件（避免四个 Controller 重复代码）

新建 `com.zjx.travel.util.MessageNotifier.java`：

```java
package com.zjx.travel.util;

import com.zjx.travel.domain.MessageEntity;
import com.zjx.travel.domain.TravelUserEntity;
import com.zjx.travel.service.MessageService;
import org.springframework.stereotype.Component;

import javax.annotation.Resource;

@Component
public class MessageNotifier {

    public static final int TYPE_SYSTEM = 0;
    public static final int TYPE_ORDER = 1;
    public static final int TYPE_AUDIT = 2;

    @Resource
    private MessageService messageService;

    /** 发送一条消息（receiverUserId 为接收人用户ID） */
    public void send(Integer receiverUserId, int type, String title, String content) {
        try {
            if (receiverUserId == null) return;
            MessageEntity m = new MessageEntity();
            TravelUserEntity u = new TravelUserEntity();
            u.setId(receiverUserId);
            m.setUserId(u);
            m.setType(type);
            m.setTitle(title);
            m.setContent(content);
            messageService.insert(m);   // insert 已自动填 isRead=0、createTime/updateTime
        } catch (Exception e) {
            e.printStackTrace();        // 消息失败只记日志，绝不影响主业务
        }
    }

    /** 审核结果通知（kind：攻略/路线/评论） */
    public void sendAuditResult(Integer receiverUserId, String kind, String name, boolean passed) {
        String content = passed
                ? "你发布的" + kind + "《" + name + "》已通过审核"
                : "你发布的" + kind + "《" + name + "》未通过审核，请修改后重新提交";
        send(receiverUserId, TYPE_AUDIT, kind + "审核结果", content);
    }

    /** 订单事件通知 */
    public void sendOrder(Integer receiverUserId, String title, String content) {
        send(receiverUserId, TYPE_ORDER, title, content);
    }
}
```

## 2. 攻略审核 → 通知发布者

改 `StrategyController.edit`（注入 `@Resource private MessageNotifier messageNotifier;`）。
**关键：用旧值对比，只有"待审核(0)"变为"通过(1)/驳回(2)"才发**——否则普通编辑/重复审核会重复打扰用户：

```java
@PostMapping("edit")
public ReturnVO edit(@RequestBody StrategyEntity strategy) {
    ReturnVO returnVO = ReturnVO.getNodataFoundReturnVO();

    // 检测审核状态变化：0 → 1/2
    boolean auditChanged = false;
    boolean auditPassed = false;
    if (strategy.getId() != null && strategy.getAuditStatus() != null
            && (strategy.getAuditStatus() == 1 || strategy.getAuditStatus() == 2)) {
        StrategyEntity old = this.strategyService.queryById(strategy.getId());
        auditChanged = old != null && old.getAuditStatus() != null && old.getAuditStatus() == 0;
        auditPassed = strategy.getAuditStatus() == 1;
    }

    if (!this.strategyService.update(strategy)) {
        return returnVO;
    }

    // 审核成功后通知发布者
    if (auditChanged) {
        Integer receiverId = strategy.getUserId() != null ? strategy.getUserId().getId() : null;
        this.messageNotifier.sendAuditResult(receiverId, "攻略", strategy.getTitle(), auditPassed);
    }

    returnVO.setCode(1);
    returnVO.setMsg("修改成功");
    return returnVO;
}
```

> ⚠️ 两个前提：① 审核提交体必须带 `userId`（前端审核对话框提交 `queryById` 里的 userId 对象即可），
> 否则 `strategy.getUserId()` 为 null，消息没有接收人；
> ② 提交体**只带业务字段**（id / userId / auditStatus / title 等），时间字段后端自理不要回传。

## 5. 订单 → 下单/支付通知（两个触发点）

`ScenicOrdersController`：

```java
// ===== add：下单成功通知 =====
if (!this.scenicOrdersService.insert(scenicOrders)) return returnVO;
if (scenicOrders.getUserId() != null && scenicOrders.getUserId().getId() != null) {
    this.messageNotifier.sendOrder(scenicOrders.getUserId().getId(), "下单成功",
            this.resolveScenicName(scenicOrders) + "门票生成订单 " + scenicOrders.getOrderNo());
}
returnVO.setCode(1);
returnVO.setMsg("添加成功");

// ===== edit：支付成功通知（payStatus 从 0 变 1 才发，避免重复支付/免费单重复通知）=====
boolean payChanged = false;
if (scenicOrders.getId() != null && scenicOrders.getPayStatus() != null && scenicOrders.getPayStatus() == 1) {
    ScenicOrdersEntity old = this.scenicOrdersService.queryById(scenicOrders.getId());
    payChanged = old != null && old.getPayStatus() != null && old.getPayStatus() == 0;
}
if (!this.scenicOrdersService.update(scenicOrders)) return returnVO;
if (payChanged && scenicOrders.getUserId() != null && scenicOrders.getUserId().getId() != null) {
    this.messageNotifier.sendOrder(scenicOrders.getUserId().getId(), "订单支付成功",
            "您预订的「" + this.resolveScenicName(scenicOrders) + "」门票订单已支付成功，凭订单号入园。");
}
```

> 景区名称由后端查库解析：控制器注入 `ScenicService`，私有方法 `resolveScenicName` 用提交体里
> `scenicId.id` 查 `scenic` 表取 `name`（前端 `scenicId` 只带 `id` 即可，不带 name 也不会出现《null》），
> 查不到时兜底显示"景区"。

> ⚠️ 前端 PayDialog 支付时走 `scenicOrders/edit`，提交体里必须带 `userId`、`scenicId` 对象
> （`OrderManagement.vue` 的编辑提交就是这个结构，可直接参考；若 PayDialog 没带，补上）。
> 时间字段（payTime/createTime）后端自理，提交体同样不要传。

## 6. 设计约定（为什么这么写）

| 约定 | 原因 |
|---|---|
| 消息插入 try-catch，失败只记日志 | 消息丢失可容忍；审核/支付失败不可接受 |
| 旧值对比（0→1/2、0→1）才发送 | 普通编辑、重复审核/重复支付不会重复打扰用户 |
| 审核请求体必须带 userId | 消息接收人来自业务数据本身，前端审核对话框记得回传 |
| 复用 `message/add` 的 insert 逻辑 | `MessageServiceImpl.insert` 已自动填 isRead=0、时间戳 |

## 7. 验收清单（改完重启后端逐项自测）

1. 管理员审核一篇"待审核"攻略 → **发布者**登录后：消息中心出现「攻略审核结果」（内容含攻略名），铃铛红点 +1
2. 同样验证：路线审核、评论审核
3. 审核同一篇"已通过"的攻略（再点通过）→ **不**产生新消息（旧值检测）
4. 普通用户购票下单 → 收到「下单成功」；支付 → 收到「订单支付成功」
5. 免费订单（payStatus=2）/重复支付 → 不产生「支付成功」消息
6. 消息类型徽章正确：审核=绿色、订单=蓝色（前端按 type 渲染）
